Start here if you have a symptom, not an error code — "my transaction is stuck" rarely comes with a code attached. If you *do* have an on-screen error message, [/reference/errors](/reference/errors) is organised by code and is faster; the entries below link into it wherever a specific code applies.

These entries are drawn from the app's own error-handling code, not invented scenarios: `apps/web/src/features/wallet/components/NetworkMismatchBanner.tsx`, `apps/web/src/shared/components/TxStatus.tsx` and `packages/contracts/src/errors.ts` (`parseSorobanError`), `apps/web/src/features/faucet/hooks/useClaim.tsx`, and `apps/docs/content/developers/reading-data.mdx`'s measured RPC/indexer latency — each entry names the file its checks came from so you can verify them yourself.

## Transaction stuck pending

**What you see:** the pending spinner in `TxStatus` ("Waiting for confirmation…") never resolves to success or failure.

Likely causes, in order:

1. **The signature dialog is still open or was missed.** A Soroban transaction only leaves "pending" once your wallet returns a signed envelope. Check the wallet extension for a pending approval popup — it can open behind the browser window.
2. **The transaction expired before inclusion** (`tx_too_late` in [/reference/errors#tx-too-late](/reference/errors#tx-too-late)). Slow signing or a busy network can push the transaction past its time bounds.
3. **The submitted fee was too low for current network conditions** (`tx_insufficient_fee`). More likely during periods of high testnet/mainnet load.
4. **The RPC node is degraded.** If every submission from your session hangs, not only one, the endpoint itself may be slow — see "Network is busy" in [/reference/errors#timeout-or-try-again](/reference/errors#timeout-or-try-again).

**Checks:**
- Look for a wallet popup, including behind other windows.
- Reload the page and check whether the transaction hash (if you have one) appears on [Stellar Expert](https://stellar.expert) — if it does, it succeeded and the UI failed to confirm; if it doesn't after a few minutes, it did not land and is safe to resubmit.
- Retry once. Soroban transactions are not resubmitted automatically by design — see [Write SO4 transactions](/developers/writing-transactions).

## Wallet will not connect

**What you see:** the connect dialog opens (`ConnectButton`) but no extension prompt appears, or the dialog closes with no wallet selected.

Likely causes, in order:

1. **The extension isn't installed, or is disabled for this site.** `ConnectButton` lists Freighter, xBull, and Hana with install links — if none show as detected, the extension either isn't installed or its "connect to this site" permission is off.
2. **A stale extension session.** Wallet extensions can hold a cached connection to a page that no longer matches the current tab state after a hard refresh or an extension update.
3. **A blocked popup.** Some wallet flows open a browser popup for approval; a popup blocker silently drops it.

**Checks:**
- Confirm the extension icon is active (not greyed out) in the browser toolbar.
- Open the extension directly and check it isn't already connected to a different account than expected — reconnecting from the app forces the extension's account picker.
- Check the browser's popup-blocked indicator in the address bar.

## Wrong network

**What you see:** the yellow banner from `NetworkMismatchBanner` — "Your wallet is connected to \{network\} but this app is running on \{network\}. Please switch networks in your wallet."

**Cause:** this banner is not a guess — it renders only when `useNetwork()` detects the wallet's active network genuinely differs from the network this deployment is running on (mainnet vs. testnet). It's the app correctly reporting an actual mismatch, not a false positive to work around.

**Checks:**
- Open the wallet extension and switch its network to match the label the banner names.
- If the banner won't go away after switching, reload the page — some wallets don't broadcast a network-change event until the next connection.
- Dismissing the banner (its "Dismiss" control) hides it for the browser tab session only; it does not fix the mismatch, and transactions will still fail or target the wrong network underneath it.

## Balance not updating

**What you see:** a token balance in the UI doesn't reflect a transaction you know completed.

Likely causes, in order:

1. **You're looking at a cached read.** Balance reads go through RPC or the indexer depending on the view; see [Read SO4 data](/developers/reading-data) for which path a given screen uses and its measured latency (RPC: ~836ms median; indexer: one local database round trip once synced).
2. **The indexer hasn't processed the ledger yet.** The indexer path only reflects ledgers it has indexed — a transaction that landed one ledger ago may not be visible there yet even though it's final on-chain.
3. **You're checking the wrong network or account.** See "Wrong network" above; also confirm the connected wallet address matches the one that sent the transaction.

**Checks:**
- Compare against [Stellar Expert](https://stellar.expert) for the account directly — if the balance is correct there but wrong in the app, it's a read-path lag, not a lost transaction.
- Hard-refresh the page to force a fresh read rather than a cached one.

## Position not appearing

**What you see:** you opened a position but it isn't listed on the positions page.

Likely causes, in order:

1. **Indexer lag**, same as "Balance not updating" above — positions listed through the indexer reflect its current sync height, not the chain tip.
2. **The order hasn't executed yet.** Opening a position through a limit or trigger order creates an *order* first; it only becomes a *position* once that order executes. Check the orders list, not only positions.
3. **The transaction that would have created it failed.** Check `TxStatus` for a failure state and the message against [/reference/errors](/reference/errors) — a position that never opened has nothing to display.

**Checks:**
- Confirm the transaction hash on Stellar Expert actually invoked `ExchangeRouter` successfully.
- Check the orders list for a pending order with the same parameters.
- Confirm you're on the same network and market you traded on.

## Chart not loading

**What you see:** the price chart is blank, stuck loading, or frozen on a stale price.

Likely causes, in order:

1. **An oracle read failed or is stale.** SO4 sources prices from more than one oracle; a temporarily stale or unavailable feed can leave the chart without fresh data rather than showing wrong data.
2. **A market data subscription dropped.** Realtime chart updates depend on a live connection; a network blip can leave the chart showing the last received point without visibly erroring.
3. **The selected market has no recent activity.** A thinly-traded market can look "stuck" because there is nothing new to plot.

**Checks:**
- Switch to a different, more active market and confirm its chart updates — this isolates whether the problem is connection-wide or market-specific.
- Reload the page to force a fresh subscription.
- If the chart is wrong rather than blank, do not trade on it — treat it the same as a price you'd verify against [Stellar Expert](https://stellar.expert) or another source before acting.

## Faucet request failing

**What you see:** a claim button that stays disabled, or an inline error under the faucet form.

Likely causes, in order:

1. **Cooldown is active.** `useClaim` shows "Cooldown active — please wait before claiming again." when the account claimed too recently — this is an intentional rate limit, not a bug.
2. **The faucet contract itself failed the call** — check the message against [/reference/errors](/reference/errors); `INSUFFICIENT_LIQUIDITY`-style contract errors can apply if the faucet's own supply is temporarily exhausted.
3. **Wallet or network problems** — see the sections above; the faucet is a normal signed transaction and fails the same ways any transaction does.

**Checks:**
- Read the inline message under the claim button before assuming it's broken — a cooldown message is expected behavior, not an error to report.
- Confirm you're connected to testnet (the faucet doesn't exist on mainnet).

## Collecting information for a bug report {#collecting-information-for-a-bug-report}

Include, if you have them:

- The exact on-screen message, and which page you were on.
- The transaction hash, if one was generated — it lets anyone check the outcome on [Stellar Expert](https://stellar.expert) without needing anything from you.
- The network (mainnet or testnet) and roughly when it happened.
- Steps to reproduce, if it wasn't a one-off.

**Never needed, and never include:** your secret key, seed phrase, or wallet password. No one — not support, not a GitHub issue, not this documentation — will ever ask you for it, and nothing in SO4's own troubleshooting flow requires it. If anything claiming to be SO4 support asks for your secret key, it is not SO4.

If your error isn't covered by [/reference/errors](/reference/errors) or any entry above, [open an issue](https://github.com/SO4-Markets/interface/issues/new) with the information above.
